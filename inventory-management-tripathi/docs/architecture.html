Filter Data Flow

Step 1
Global State
4 singleton refs in useFilters.js
Shared by every component via module-level scope

selectedPeriod
selectedLocation
selectedCategory
selectedStatus
›
Step 2
FilterBar UI
FilterBar.vue binds each <select> via v-model directly to the shared refs.

Changing any dropdown mutates the singleton immediately — no emit needed.
›
Step 3
View Reactivity
Each view uses watch([...filters]) to re-trigger loadData() on any change.

getCurrentFilters() maps refs → API params (e.g. selectedLocation → warehouse)
›
Step 4
API Call
api.js serializes only non-'all' values into URLSearchParams.

Absent = unfiltered on the backend.
›
Step 5
Backend Filter
apply_filters() chains list comprehensions:

warehouse exact match
category case-insensitive
status case-insensitive
month substring in date string
Quarter support: Q1-2025 → 3-month array
›
Step 6
Special Cases
Demand & Backlog have no backend filters.

Frontend fetches filtered inventory → extracts SKU set → client-side filters demand/backlog by SKU match.

Spending period filter is entirely client-side computed.

Notable Patterns & Quirks

🔵
Singleton composable for shared filter state
useFilters.js declares its 4 refs at module scope — outside the exported function. Every component calling useFilters() gets the same ref instances, making FilterBar changes instantly reactive across all views with no prop drilling or event bus.
🟡
Reports.vue is the architectural outlier
Every other view uses Composition API, useFilters(), and api.js. Reports.vue uses the older Options API, imports axios directly with hardcoded localhost:8001 URLs, has no filter integration, and contains console.log statements — it appears to be an early draft.
🔴
Stub features: tasks + purchase orders
api.js defines 6 functions (getTasks, createTask, deleteTask, toggleTask, createPurchaseOrder, getPurchaseOrderByBacklogItem) that call endpoints which don't exist in main.py. The Dashboard has "Create PO" buttons and the Pydantic models are defined, but the routes and data are not implemented.
🟠
Backlog.vue is an orphaned view
client/src/views/Backlog.vue is a complete standalone view but was never added to the router in main.js. The backlog table is rendered directly inside Dashboard.vue instead — the file is unreachable from the app.
🟢
Demand & Backlog filtering is client-side
The /api/demand and /api/backlog endpoints accept no filter parameters and always return all data. Instead, the frontend fetches filtered inventory first, builds a Set of valid SKUs, then filters demand/backlog results by SKU membership — effectively delegating the filtering to a secondary cross-reference step.
🟣
i18n and currency are tightly coupled to locale
Switching to Japanese locale (JA) via LanguageSwitcher automatically switches all currency display to JPY at a hardcoded 150:1 conversion rate via useI18n.js. Locale preference is persisted to localStorage.
